How to Write Custom DPI Rules Quick Reference & Templates
1. Rule Syntax
<action> <proto> any any -> any any (msg:"..."; content:"..."; nocase; sid:9000001; rev:1;)
2. Actions & Protocols
  • drop / reject — Blocks immediately (injects TCP RST or drops UDP) & logs ATTACK DETECTED.
  • alert — Audit mode: logs match to Security Logs without resetting the connection.
  • tcp, http, tls — Inspects inbound TCP & decrypted HTTPS streams. Use ip to match both TCP and UDP.
3. Supported Options
  • msg:"..." — Human-readable alert name shown in logs.
  • content:"..." — Literal bytes to match. Hex bytes go inside pipes: |0d 0a|. Short strings (< 6 bytes) are allowed in custom rules.
  • nocase; — Makes the preceding content case-insensitive.
  • offset:N; depth:N; — Restrict match window from start of payload.
  • distance:N; within:N; — Distance/window after previous content.
  • pcre:"/regex/i"; — Hyperscan-compatible regex (i = caseless).
  • sid:<num>; — Unique rule ID (recommended 9000001+).
4. Ready-to-Use Templates (Click to Prefill)
Block Sensitive Path (/admin or .env)
drop http any any -> any any (msg:"CUSTOM Dotenv Exposure Probe"; content:"/.env"; nocase; sid:9000001; rev:1;)
Block Malicious User-Agent / Scanner
drop http any any -> any any (msg:"CUSTOM Block sqlmap User-Agent"; content:"sqlmap/"; nocase; sid:9000002; rev:1;)
Regex SQL Injection (pcre)
drop tcp any any -> any any (msg:"CUSTOM SQLi UNION SELECT"; pcre:"/union\s+(all\s+)?select/i"; sid:9000003; rev:1;)
Audit-Only Rule (Log Without Dropping)
alert tcp any any -> any any (msg:"CUSTOM Audit Debug Header"; content:"X-Debug-Token|3a|"; nocase; sid:9000004; rev:1;)
